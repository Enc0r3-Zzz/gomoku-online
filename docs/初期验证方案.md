# 初期验证方案（无公网服务器）

> 结论：**不需要公网服务器**。本机一个进程 + 本机 MySQL 8（已运行）即可完成 90% 的验证；局域网和临时隧道只用于"跨设备/外网演示"。

## 验证原则

1. 分层验证：越靠下越快、越稳定；越靠上越接近真实体验。
2. 每个需求至少一条**自动化断言** + 一条**手工演示路径**。
3. 所有验证结果留证据（测试报告、截图、压测数据），直接对应课程报告的「系统验证」章节。
4. 不依赖 HTTPS、不依赖公网、不依赖云数据库。

## 验证矩阵

| 层级 | 验证内容 | 运行方式 | 依赖 |
| --- | --- | --- | --- |
| L0 单元 | 棋局规则、ELO、校验器、密码策略 | `mvn test` | 无 |
| L1 集成 | 注册/登录/榜单 REST、安全控制 | `@SpringBootTest` + MockMvc | 本机 MySQL 或 Testcontainers |
| L2 WS 双端 | 匹配→对局→聊天→结算 全链路 | 同 JVM 两个 WebSocket 客户端 | 本机 MySQL |
| L3 浏览器 | 真实 UI、会话、断线重连、XSS | localhost 双浏览器 | 无 |
| L4 局域网 | 跨设备真实网络 | 手机访问 `http://10.4.250.84:8080` | 同一 WiFi |
| L5 公网 | 远程演示/老师预览 | ngrok / cloudflared 隧道 | 本机常开 |
| L6 压测 | 并发连接、落子延迟、榜单响应 | k6 / JMeter | 无 |

## L0：单元测试（毫秒级，先跑这个）

不启动 Spring，纯 JUnit 5：

- `GameEngine`：横/竖/两斜五连；边界落子；长连判胜；满盘和棋；重复落子拒绝；非当前回合拒绝。
- `EloCalculator`：同分 ±16、高低分期望值、K 值切换、0 分保底。
- 密码策略：长度/复杂度/BCrypt 校验。
- 协议编解码：非法 JSON、未知 op、超大消息。

命令：

```bash
mvn test
```

## L1：集成测试（真实 HTTP + 真实数据库）

两种跑法，二选一：

1. **Testcontainers**（推荐，隔离干净）：需要 Docker Desktop 正在运行。当前本机 Docker 已安装但守护进程未启动，需先打开 Docker Desktop。
2. **本地 MySQL 测试库**：新建 `gomoku_test` 库，`application-test.yml` 指向它，Flyway 每次重建。本机 MySQL80 已在 3306 运行，最省事。

覆盖：

- `POST /register`：重复用户名 409、弱密码 400、成功后库中为 BCrypt。
- `POST /login`：正确/错误、5 次失败锁定、会话建立。
- `GET /api/leaderboard`：未登录 401；登录后 Top N 与我的排名正确。
- 越权：用户 A 不能读取 B 的对局/聊天。
- CSRF：无 token 的表单提交被拒绝。

## L2：WebSocket 双端协议测试（无浏览器验证后端闭环的关键）

同一个 JVM 里起两个 `StandardWebSocketClient`，连真实 `ws://localhost:8080/ws/game`：

```
HTTP 注册/登录 alice、bob → 各拿会话 Cookie
WS 握手带 Cookie → 两条连接
alice: QUEUE_JOIN，bob: QUEUE_JOIN
断言双方收到 MATCH_FOUND（一黑一白，roomId 相同）
按轮次交替 MOVE，直到五连
断言双方收到 GAME_OVER（胜负正确）
断言 DB：matches、moves、users.rating、rating_history 一致
```

伪代码：

```java
var client = new StandardWebSocketClient();
var headers = new WebSocketHttpHeaders();
headers.add(HttpHeaders.COOKIE, sessionCookie);
WebSocketSession ws = client.execute(handler, "ws://localhost:8080/ws/game", headers).get(5, SECONDS);
```

这一层跑通，说明「后端 + 协议 + 数据库」闭环完成，剩下的只是 UI。

## L3：浏览器双会话（真实体验）

- **两个浏览器**：Chrome 正常窗口 + Edge，或 Chrome + 无痕窗口（Cookie 隔离）。
- 流程：各自注册/登录 → 同时点匹配 → 对局 → 聊天 → 一方五连 → 榜单分数变化。
- 断线重连：直接关掉一方标签页，60 秒内重新打开对局 URL → 棋盘、轮次、聊天恢复。
- XSS：聊天输入 `<script>alert(1)</script>`，断言原样显示为文本、不弹窗。
- 证据：截图 + 录屏（答辩和报告直接用）。

> Playwright 也能做双 context 自动化，但它是 Node 工具链；本项目选 Thymeleaf + 原生 JS，若要做 Java 侧 E2E 可用 Selenium 4。课程演示阶段手工即可。

## L4：局域网真机（跨设备）

- Spring Boot 默认监听 `0.0.0.0`，本机 IP **10.4.250.84**。
- Windows 防火墙首次启动会弹窗，勾选「专用网络」允许。
- 手机浏览器访问 `http://10.4.250.84:8080`。
- 若校园网开了 AP 隔离导致不通：手机开热点让电脑连，或直接用 L5 隧道。

## L5：公网临时演示（无服务器方案）

本机已装 **ngrok 3.25.0**（`~/.ngrok2/ngrok.yml` 已有配置）：

```bash
ngrok http 8080
# → https://xxxx.ngrok-free.app
```

- 免费版每个浏览器会话首次会弹一次警告页，点「Visit Site」即可；WebSocket 走 `wss://` 正常。
- 免费版 URL 每次重启会变，1 条隧道；电脑休眠/断网即失效。

更干净的替代：**cloudflared quick tunnel**（无需账号）：

```bash
cloudflared tunnel --url http://localhost:8080
# → https://xxx.trycloudflare.com（无警告页）
```

注意：

- 前端 WebSocket 地址用 `location.host` 推导，localhost / 局域网 / 隧道自动适配，不需要改配置。
- 开发 profile 的会话 Cookie 用 `Secure=false`（否则 http://localhost 带不上 Cookie）；走隧道 HTTPS 时仍然可用。
- 答辩现场优先本地演示；隧道只作为「老师远程看一眼」的备选，不要把它当正式部署。

## L6：性能验证

- 工具：k6（原生支持 WebSocket）或 JMeter WebSocket Sampler。
- 场景：200 个连接、50 对同时匹配、持续 5 分钟；记录落子 p95 延迟、榜单 p95、CPU/内存。
- 单机跑即可；报告里注明测试机配置和「单机、无反向代理」的前提。

## 一个人怎么测？

1. **两个浏览器会话**：Chrome + Edge，各注册一个账号。
2. **开发用机器人**：`@Profile("dev")` 的 `BotPlayer`，开关 `gomoku.bot.enabled=true`；入队后自动接单，用「先堵后连」的简单启发式落子。作用：
   - 单人也能走完整对局；
   - 现场网络出问题时作为演示兜底；
   - 可给聊天发固定台词，验证消息收发。
3. **脚本化客户端**（L2）：两个 WS 客户端即两个"玩家"，适合回归测试。

## 答辩演示脚本（5 分钟）

1. 注册 alice / bob → 展示密码库中为 BCrypt。
2. 双浏览器登录 → 大厅 → 同时匹配。
3. 对局：落子动画、最后一手高亮、聊天、认输/五连。
4. 结算：本局 ±分 → 榜单排名变化。
5. 断线重连：关标签页 → 重开恢复。
6. （可选）手机连局域网或 ngrok 地址，展示跨设备。
