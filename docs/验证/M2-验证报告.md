# M2 验证报告 · 棋局引擎、匹配与 WebSocket

> 日期：2026-11-04　｜　方式：42 个自动化用例（含真实 WebSocket 双客户端）+ 页面渲染检查

## 1. 本层交付

| 能力 | 实现 |
| --- | --- |
| 棋盘规则 | 15×15，黑先，四方向五连（含长连）判胜，满盘判和 |
| 对局持久化 | `game_matches` / `moves`，每一步落子落库，可重放 |
| 服务端权威 | 轮次、坐标、空位、序号、胜负全部由服务端校验 |
| 匹配 | 内存等待队列，评分差 100 起、每 5 秒放宽 50、上限 400 |
| WebSocket | `/ws/game`，自定义 JSON 协议，握手支持会话 Cookie + 短时 ticket |
| 断线 | 掉线通知对手，60 秒宽限（重连逻辑 M3 完善） |
| 计时 | 每步 30 秒，服务端定时判超时负 |
| 前端 | 大厅匹配按钮 + 等待状态；对局页 Canvas 棋盘、双方信息、倒计时、认输、结果弹层 |
| 事务消息 | 所有广播在事务提交后发送，避免客户端看到未落库状态 |

协议：`QUEUE_JOIN / QUEUE_LEAVE / RESUME / MOVE / RESIGN / PING` → `QUEUED / MATCH_FOUND / STATE / MOVE / GAME_OVER / OPPONENT_LEFT / ERROR / PONG`。

## 4. WebSocket 认证说明

浏览器默认用会话 Cookie；但部分 WS 客户端（含测试用的 Tomcat 客户端）不会转发自定义 `Cookie` 头，因此增加短时 ticket：

- 页面渲染时签发，TTL 5 分钟，绑定 userId；
- 连接地址 `/ws/game?ticket=...`；
- `WsTicketInterceptor` 校验 ticket；无 ticket 时回退会话认证；
- `/ws/**` 在 Security 中放行，由握手拦截器/处理器负责认证，未认证连接以 4401 关闭。
