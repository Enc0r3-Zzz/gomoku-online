# M1 验证报告 · 登录锁定、限流与安全加固

> 日期：2026-11-04　｜　方式：自动化测试 + 本机 MySQL 8.0.45 端到端

## 1. 本层交付

| 能力 | 实现 |
| --- | --- |
| 登录失败锁定 | 用户名 + IP 计数，5 次失败锁 15 分钟；成功登录清零；到期自动释放 |
| 登录前置拦截 | `LoginLockFilter` 在认证前拦截已锁定账号，正确密码也无法登录 |
| 注册限流 | 每 IP 10 分钟 5 次，超出提示「操作过于频繁」 |
| 安全响应头 | CSP、X-Frame-Options=DENY、Referrer-Policy、Permissions-Policy、X-Content-Type-Options |
| API 未认证 | `/api/**` 返回 401，页面路由仍跳登录页 |
| 审计日志 | 登录成功/失败、锁定、注册写 `AUDIT` logger |
| 并发注册兜底 | 捕获唯一键冲突 `DataIntegrityViolationException` |

配置项（`application.yml`）：

```yaml
gomoku:
  security:
    login-max-failures: 5
    login-lock-duration: 15m
    register-max-per-window: 5
    register-window: 10m
```

## 4. 说明与边界

- 锁定与限流为**单实例内存实现**，重启清零；多实例部署需换 Redis/数据库，报告「方案论证」中说明。
- 锁定 key 为 `username|ip`，避免同一 IP 下其他账号被误锁，也避免单账号被多 IP 绕过。
- 注册限流按 IP，未按用户名；后续可叠加验证码。
- 测试数据已清理（仅保留你手动注册的 `zzz114514`）。
