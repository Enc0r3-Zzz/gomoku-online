# 答辩演示脚本（5 分钟）

## 演示前 10 分钟

1. 确认 MySQL80 服务运行，`gomoku` 库存在。
2. 运行 `scripts\dev.bat`，确认 <http://localhost:8080/login> 返回登录页。
3. 准备两个浏览器：Chrome 正常窗口 + Edge（或无痕窗口），Cookie 隔离。
4. 准备两个账号：`demo_a` / `demo_b`（密码 `gomoku123`），或现场注册。
5. 关闭无关窗口，浏览器缩放 100%。

## 兜底方案

- 匹配失败：刷新两个页面重试；或直接用测试账号登录后重新匹配。
- 网络/端口异常：改用已导出的 PDF 报告 + PPT 截图讲解。
- 现场不允许外网：全部本地运行，不依赖 GitHub/隧道。

## 常见提问

- **为什么不用 P2P？** 浏览器真 P2P 需 WebRTC + 信令 + STUN/TURN；排位结果无法服务端验证，五子棋回合制对延迟不敏感。报告中给出对比。
- **为什么用会话不用 JWT？** 同源部署，HttpOnly Cookie 对 XSS 更稳；WS 握手可直接复用登录态。
- **服务端如何防作弊？** 轮次、坐标、胜负、超时全部服务端裁决；客户端只渲染；moves 可回放审计。
- **断线怎么处理？** 60 秒宽限，RESUME 按 seq 重放；超时判负；双方都掉线 ABORT 不计分。
- **AI 做了什么？** 规格→生成→测试→人工审批→回归；AI 写样板/测试/文档，人工定边界、协议、评分与安全策略。
