# 五子棋在线对战 · 项目实现方案

> 决策基线：Spring Boot 3.x + Java 17 + MySQL 8 + Spring Data JPA；Thymeleaf + 原生 JS；服务端权威 WebSocket 中继（不做 P2P）；传统软件工程 + AI 工程化；ELO 天梯（可降级）。

## 4. 数据模型

### 4.1 表结构

```sql
CREATE TABLE users (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  username      VARCHAR(32)  NOT NULL UNIQUE,
  password_hash VARCHAR(100) NOT NULL,
  nickname      VARCHAR(32)  NOT NULL,
  rating        INT          NOT NULL DEFAULT 1200,
  wins          INT          NOT NULL DEFAULT 0,
  losses        INT          NOT NULL DEFAULT 0,
  draws         INT          NOT NULL DEFAULT 0,
  created_at    DATETIME(6)  NOT NULL,
  version       BIGINT       NOT NULL DEFAULT 0,
  KEY idx_users_rating (rating DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE game_matches (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  black_id   BIGINT      NOT NULL,
  white_id   BIGINT      NOT NULL,
  status     VARCHAR(16) NOT NULL,          -- WAITING/PLAYING/FINISHED/ABORTED
  result     VARCHAR(16),                   -- BLACK_WIN/WHITE_WIN/DRAW/ABORT
  winner_id  BIGINT,
  started_at DATETIME(6) NOT NULL,
  ended_at   DATETIME(6),
  version    BIGINT      NOT NULL DEFAULT 0,
  KEY idx_matches_black (black_id),
  KEY idx_matches_white (white_id)
  -- 外键 black_id / white_id / winner_id → users.id（略）
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE moves (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  match_id   BIGINT      NOT NULL,
  seq        INT         NOT NULL,
  player_id  BIGINT      NOT NULL,
  x          TINYINT     NOT NULL,
  y          TINYINT     NOT NULL,
  created_at DATETIME(6) NOT NULL,
  UNIQUE KEY uk_move_seq (match_id, seq)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE chat_messages (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  match_id   BIGINT       NOT NULL,
  sender_id  BIGINT       NOT NULL,
  content    VARCHAR(200) NOT NULL,
  created_at DATETIME(6)  NOT NULL,
  KEY idx_chat_match (match_id, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE rating_history (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id       BIGINT NOT NULL,
  match_id      BIGINT NOT NULL,
  rating_before INT    NOT NULL,
  rating_after  INT    NOT NULL,
  delta         INT    NOT NULL,
  created_at    DATETIME(6) NOT NULL,
  KEY idx_rh_user (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 实体要点

- `User`：`@Version` 乐观锁；密码只存哈希。
- `GameMatch`：`status` 枚举；`@Version` 防并发结算。
- `Move`：`(match_id, seq)` 唯一，保证幂等与顺序。
- 不建 `board` 列：棋盘由 `moves` 重放，天然支持回放/重连。
- `ddl-auto=validate`，schema 只由 Flyway 改。

## 5. 页面与接口

### 5.1 页面

| 路径 | 内容 | 渲染 |
| --- | --- | --- |
| `/` | 未登录→`/login`，已登录→`/lobby` | 重定向 |
| `/login` | 表单登录 | Thymeleaf |
| `/register` | 注册表单 | Thymeleaf |
| `/lobby` | 用户卡片、评分、匹配按钮、榜单入口 | Thymeleaf + `lobby.js` |
| `/game/{id}` | 棋盘、双方信息、计时、聊天、认输 | Thymeleaf 壳 + `game.js` |
| `/leaderboard` | Top 50 + 我的排名 | Thymeleaf 服务端渲染 |
| `/error` | 403/404/500 | Thymeleaf |

### 5.2 REST

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/register` | 注册（表单，CSRF） |
| POST | `/login` | Spring Security 表单登录 |
| POST | `/logout` | 登出 |
| GET | `/api/me` | 当前用户摘要（评分/战绩） |
| GET | `/api/leaderboard?limit=50` | 榜单 + 我的排名 |
| GET | `/api/matches/{id}` | 对局元信息（参与者校验） |
| GET | `/actuator/health` | 健康检查 |

> 落子/聊天/认输**不走 REST**，统一走 WebSocket，避免双通道状态不一致。

### 5.3 WebSocket

端点：`/ws/game`（原生 WebSocket）。握手复用会话 Cookie，`WsAuthInterceptor` 校验登录态与 `Origin`。

消息信封：

```json
{ "op": "MOVE", "seq": 3, "data": { "x": 7, "y": 8 } }
```

客户端 → 服务端：

| op | data | 说明 |
| --- | --- | --- |
| `QUEUE_JOIN` | — | 入匹配队列 |
| `QUEUE_LEAVE` | — | 退出队列 |
| `MOVE` | `{x,y,seq}` | 落子 |
| `CHAT` | `{text}` | 聊天 |
| `RESIGN` | — | 认输 |
| `RESUME` | `{matchId,lastSeq}` | 重连恢复 |
| `PING` | — | 心跳 |

服务端 → 客户端：

| op | data | 说明 |
| --- | --- | --- |
| `QUEUED` | `{since}` | 已入队 |
| `MATCH_FOUND` | `{matchId,color,opponent}` | 匹配成功，跳转 `/game/{id}` |
| `STATE` | `{board,moves,turn,seq,deadline}` | 全量状态（重连/入场） |
| `MOVE` | `{seq,x,y,playerId,nextTurn,deadline}` | 广播落子 |
| `CHAT` | `{senderId,senderName,text,at}` | 广播聊天 |
| `GAME_OVER` | `{result,winnerId,deltas}` | 结算 |
| `OPPONENT_LEFT` | `{graceSeconds}` | 对手掉线 |
| `OPPONENT_BACK` | — | 对手重连 |
| `ERROR` | `{code,message}` | 错误 |
| `PONG` | — | 心跳响应 |

错误码：`NOT_YOUR_TURN`、`INVALID_MOVE`、`GAME_OVER`、`RATE_LIMITED`、`MESSAGE_TOO_LONG`、`SEQ_MISMATCH`、`ALREADY_QUEUED`、`NOT_IN_GAME`。

约束：单条消息 ≤ 4KB；同一用户仅保留一条活跃连接（新连接顶掉旧连接）；发送用 `ConcurrentWebSocketSessionDecorator` 保证线程安全。

## 6. 核心流程

### 6.1 注册 / 登录

```
注册: GET /register → POST /register
  → 参数校验（用户名 3-16、密码 8-72 含字母数字）
  → 唯一性检查 → BCrypt(12) → 落库 → 302 /login
登录: POST /login (Spring Security)
  → LoginAttemptService 检查锁定（5 次失败锁 15 分钟）
  → 成功: 建立会话 → /lobby；失败: 计数 +1 → /login?error
```

### 6.2 匹配

```
双方 WS 连接 → QUEUE_JOIN
MatchmakingService:
  入队（同一 userId 幂等）
  每秒扫描: 按入队时间排序，评分差 ≤ 100+50×等待秒数/5（上限 400）配对
  配对成功: 事务内插入 game_matches(WAITING) → 双方 MATCH_FOUND
  双方跳转 /game/{id} → WS 重连 → RESUME → 双方就绪 → status=PLAYING，生成首步 deadline
```

### 6.3 对局

```
点击棋盘 → 本地预检（轮次/空位）→ MOVE{x,y,seq}
服务端（房间锁内）:
  status=PLAYING？轮到该玩家？坐标合法？空位？seq=last+1？
  → 落子到内存棋盘 → 插入 moves → lastSeq++
  → 五连判定 → 未结束: 广播 MOVE + 计算下一手 deadline
               已结束: 结算（见 6.4）→ 广播 GAME_OVER
客户端收到 MOVE 才更新棋盘（服务端权威，不做乐观落子）
```

计时：每步 30 秒，服务端每秒扫描房间，超时判对手胜。

### 6.4 结算

```
win/lose/draw/resign/timeout → 事务:
  game_matches.status=FINISHED, result, winner_id, ended_at
  users.rating/wins/losses/draws 更新（@Version 乐观锁，冲突重试一次）
  rating_history 插入双方记录
  → 广播 GAME_OVER{result,deltas}
  → 5 分钟后清理内存房间（DB 保留对局记录）
```

ELO：初始 1200；`E=1/(1+10^((Rb-Ra)/400))`；`K=32`（<30 局）/`16`（≥30 局）；下限 100；平局各 0.5。

### 6.5 断线与重连

```
WS 关闭 → 标记离线，3 秒后通知对手 OPPONENT_LEFT（避免页面跳转误报）
  → 60 秒宽限
  → 期间 RESUME: 校验参与者，回 STATE，通知对手 OPPONENT_BACK
  → 超时: 判离线方负 → GAME_OVER
双方都离线 → ABORTED，不计分
```

### 6.6 聊天

```
CHAT{text} → 去空白 → 长度 ≤200 → 频率 ≤1 条/秒 → 落库 → 广播房间两人
渲染一律用 textContent，禁止 innerHTML
```

## 7. 状态机

```
GameMatch: WAITING ──双方就绪──> PLAYING ──五连/认输/超时/满盘──> FINISHED
                └────────双方都离开────────> ABORTED

连接: CONNECTED ──WS关闭──> OFFLINE ──60s内RESUME──> CONNECTED
                                   └──超时──> 判负
```

## 8. 安全设计

| 面 | 措施 |
| --- | --- |
| 密码 | BCrypt strength 12；8–72 字节；字母+数字 |
| 会话 | HttpOnly + SameSite=Lax；30 分钟超时；登录后 session fixation 防护 |
| CSRF | 表单由 Thymeleaf 自动带 token；fetch 从 meta 读 `X-CSRF-TOKEN` |
| 登录爆破 | 用户名+IP 计数，5 次失败锁 15 分钟；注册/登录接口限流 |
| XSS | Thymeleaf 默认转义；JS 用 `textContent`；CSP `script-src 'self'` |
| SQL 注入 | JPA 参数绑定，禁止字符串拼接 SQL |
| 越权 | 对局页/状态接口校验 userId ∈ {black,white} |
| WebSocket | 握手校验会话与 Origin；消息大小限制；聊天/落子限流 |
| 错误暴露 | 统一异常处理，不返回堆栈 |
| 审计 | 登录成功/失败、注册、对局结算写日志 |
| 配置 | 数据库口令走环境变量；数据库账号最小权限 |

## 9. 前端设计

- 布局：顶部栏（昵称/评分/退出）+ 主区；对局页左棋盘右信息，聊天在棋盘正下方（满足"棋盘下方聊天栏"）。
- 棋盘：Canvas 15×15，木纹底、星位、坐标、悬停预览、落子缩放动画、最后一手红点、胜利连线高亮；按 `devicePixelRatio` 缩放保证清晰。
- 响应式：`min(90vw, 640px)` 正方形；窄屏聊天栏折叠。
- 计时：倒计时环/数字，以服务端 `deadline` 为准，本地插值。
- 匹配：大厅按钮变"匹配中… 已等待 Ns"，支持取消。
- 结算：弹窗展示胜负、±分、按钮「再来一局 / 看榜单」。
- 样式：CSS 变量统一色板（暖木色 + 米白 + 墨黑），无框架，约 300 行。

## 10. 并发与一致性

- 房间级 `ReentrantLock`：同一对局的落子串行化。
- 匹配调度器单线程（`@Scheduled(fixedDelay=1000)`），避免并发配对。
- 结算事务 + `@Version`；冲突重试一次后报错。
- WS 会话注册表 `ConcurrentHashMap`；广播用线程安全装饰器。
- 内存与 DB：落子先写 DB 再广播（或同事务内），保证重连可重放。
- 已知边界：单实例；重启丢失进行中对局（报告注明）。
