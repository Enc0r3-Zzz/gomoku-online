# AI 变更审批门禁

> 原则：AI 可以生成代码与测试，但不能自行决定高风险边界。以下变更必须先停下，由人工确认后再合入。

## 门禁清单

| 门禁 | 触发条件 | 审批人 | 必须提供的证据 | 本项目实际决策 |
| --- | --- | --- | --- | --- |
| G1 认证/会话 | 修改登录、密码、Cookie、CSRF、JWT | 项目负责人（学生） | 安全用例通过；威胁点说明 | 选择会话 Cookie；BCrypt 12；CSRF 保持开启 |
| G2 数据库迁移 | 新增/修改 Flyway SQL | 项目负责人 | SQL diff、回滚方案、`ddl-auto=validate` 通过 | V1 schema + V2 坐标改 INT |
| G3 WebSocket 鉴权 | 改握手、ticket、会话注册 | 项目负责人 | 未认证连接被拒；双端测试通过 | 会话 + 5 分钟 ticket；4401 关闭未认证 |
| G4 评分逻辑 | 改 ELO/K 值/结算 | 项目负责人 | 公式推导、单测、历史流水校验 | K=32/16；下限 100；ABORT 不计分 |
| G5 P2P/架构 | 引入 WebRTC/改通信模型 | 项目负责人 + 课程要求 | 方案对比、排位可信性分析 | 不做真 P2P；服务端权威中继 |
| G6 安全头/限流 | 改 CSP、限流阈值、锁定策略 | 项目负责人 | 安全测试、误伤评估 | 5 次/15 分钟；注册 5 次/10 分钟/IP |
| G7 依赖/部署 | 新增依赖、改 Docker/端口 | 项目负责人 | 构建通过、部署验证 | 单实例；MySQL 3307 映射 |

## 执行方式

1. AI 在改动前说明触发哪个门禁。
2. 人工确认“允许/拒绝/回到需求”。
3. 允许后，AI 先补测试，再改实现。
4. 测试通过后，人工复核 diff 并提交。
5. 拒绝时，记录原因到 `prompt-log.md`，回到规格重新定义边界。
